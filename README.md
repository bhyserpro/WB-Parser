# WB-Parser — цены и снижения цен на iPhone 16 с Wildberries

Сбор выдачи по запросу «iPhone 16», фильтр аксессуаров, история цен в SQLite, анализ снижений и уведомления в Telegram.

## Как это работает и почему так

Выдача берётся из того же JSON API, что использует сам сайт:
`https://www.wildberries.ru/__internal/search/exactmatch/ru/common/v18/search`.
Это быстрее и надёжнее разбора HTML.

API закрыт антиботом WB (`wbaas`): токен проверки (`x_wbaas_token`) WB принимает **только от того браузера, где проверка пройдена**. Проверено: даже точная копия запроса из Firefox, отправленная из терминала через `curl`, получает `498`. Поэтому основной способ — сбор внутри вашего браузера:

```
Firefox (вкладка WB + userscript)  ──JSON выдачи──▶  receiver.py на 127.0.0.1  ──▶  SQLite + анализ  ──▶  Telegram
```

- **`wb-monitor.user.js`** — userscript для Tampermonkey/Violentmonkey. Сам запросов к API WB не делает (такие запросы WB отклоняет с `403`, даже изнутри страницы): выдачу запрашивает сайт — при открытии страницы поиска, при прокрутке вниз и при переходе на `&page=N`, — а скрипт перехватывает эти ответы и пересылает на ваш компьютер. Раз в час вкладка открывает выдачу заново, проверку WB проходит сам браузер. Наружу, кроме WB, ничего не уходит.
- **`receiver.py`** — локальный приёмник: разбор, фильтр, дедупликация, история цен, анализ снижений, Telegram.
- **`wb_parser.py`, `monitor.py`, `wb_token.py`** — сбор напрямую из Python через Playwright или импортированный токен. Сейчас WB такие запросы не пропускает (см. раздел в конце), но код оставлен: разбор, фильтр, экспорт и анализ общие для всех способов.

## Установка

Нужен Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Мониторинг через браузер (рекомендуется)

1. **Telegram.** Скопируйте `.env.example` в `.env` и заполните `TELEGRAM_BOT_TOKEN` (от [@BotFather](https://t.me/BotFather)) и `TELEGRAM_CHAT_ID` (например, через [@userinfobot](https://t.me/userinfobot)). Напишите боту `/start`.
2. **Приёмник.** Запустите и не закрывайте терминал:
   ```bash
   python3 receiver.py
   ```
   При первом запуске он создаст `RECEIVER_SECRET`, допишет его в `.env` и напечатает в логе: `секрет для userscript: …`. Для проверки без Telegram: `python3 receiver.py --dry-run`.

   На Mac, чтобы компьютер не засыпал, пока идёт мониторинг: `caffeinate -i python3 receiver.py`.
3. **Расширение.** Установите в Firefox [Violentmonkey](https://addons.mozilla.org/firefox/addon/violentmonkey/) или [Tampermonkey](https://addons.mozilla.org/firefox/addon/tampermonkey/).
4. **Userscript.** Откройте в Firefox файл `wb-monitor.user.js`, например перетащите его в окно браузера: расширение предложит установить. Или создайте новый скрипт в расширении и вставьте содержимое файла.
5. **Вкладка мониторинга.** Откройте в отдельном окне Firefox:
   ```
   https://www.wildberries.ru/catalog/0/search.aspx?search=iPhone%2016#wb-monitor
   ```
   При первом запуске скрипт спросит секрет — вставьте значение `RECEIVER_SECRET`.

   Скрипт работает только в этой вкладке (метка `#wb-monitor`); остальные вкладки WB он не трогает. В правом нижнем углу — плашка статуса: «страниц N, iPhone M, снижений K, следующий запуск в ЧЧ:ММ».

Готово: раз в час (±1 мин) вкладка перезагружается, собирает выдачу и отправляет её в приёмник, а в Telegram приходят только снижения цен.

**Ошибки:**
- **Токен протух** (`498`/`403`): вкладка просто перезагружается через минуту, и сайт сам проходит проверку заново. Если ошибка повторилась 3 раза подряд, в Telegram приходит ⚠️.
- **Капча или проверка висит дольше 10 минут:** в Telegram приходит ⚠️ — откройте вкладку и пройдите проверку руками.
- **Данных нет дольше 3 часов** (Firefox закрыт, Mac спит): `receiver.py` пришлёт ⚠️ сам. Порог задаётся `--max-silence-hours`.

**Сузьте выдачу фильтрами.** По запросу «iPhone 16» у WB сотни тысяч товаров, почти все — аксессуары. Пролистать их все нельзя и не нужно:
1. Откройте поиск, поставьте фильтры «Категория: Смартфоны», «Бренд: Apple» (по желанию — сортировку «Сначала дешёвые»).
2. Скопируйте адрес страницы в `CONFIG.searchUrl` в начале скрипта, например:
   ```js
   searchUrl: 'https://www.wildberries.ru/catalog/0/search.aspx?search=iPhone%2016&xsubject=515&fbrand=6049',
   ```
   Параметры фильтров берите из своего адреса, а не из примера.
3. Откройте этот адрес, добавив `#wb-monitor` в конце.

**Откуда берутся данные.** Основной источник — ответы API, которые получает сам сайт. Если перехват их не видит (Violentmonkey в Firefox иногда запускает скрипт уже после того, как сайт начал работать), скрипт читает карточки товаров на странице: артикул, название, цена, старая цена, рейтинг, отзывы. В этом режиме нет продавца и цвета, а плашка пишет «с карточек N (без продавца)».

Чтобы перехват успевал, включите в Violentmonkey: ⚙ Настройки → Дополнительно → **Синхронный режим page** (Synchronous page mode) и перезагрузите вкладку. В консоли Firefox строка «перехват не поймал ответов API (в Network запросов поиска: N)» показывает, сработал ли перехват.

**Настройки** — в начале `wb-monitor.user.js`, объект `CONFIG`:
- `query` — поисковый запрос;
- `searchUrl` — свой адрес выдачи с фильтрами (см. выше); `null` — поиск по `query`;
- `intervalMin` — период сбора, мин;
- `maxPages` — максимум страниц выдачи (по ~100 товаров, по умолчанию 50);
- `delayMinMs` / `delayMaxMs` — пауза между страницами;
- `receiver` — адрес приёмника.

Регион доставки и прочие параметры — те, что использует сам сайт, то есть ваш регион.

Параметры `receiver.py`:
- `--min-drop-pct`, `--min-drop-rub` — пороги снижения;
- `--min-price` — граница цены смартфона;
- `--export results/last.xlsx` — сохранять XLSX/CSV каждого запуска;
- `--db` — путь к базе;
- `--port` — порт приёмника; при смене поменяйте `receiver` в `CONFIG`.

> Firefox замедляет таймеры в фоновых вкладках. Держите вкладку мониторинга в отдельном окне: тогда сбор не растянется.

**Безопасность.** Приёмник слушает только `127.0.0.1` и принимает данные только с заголовком `X-Auth-Token`, равным `RECEIVER_SECRET`, поэтому другие сайты в браузере не могут подсунуть ему данные. `.env` в `.gitignore`.

## Разовый сбор: `wb_parser.py`

> Сейчас WB не пропускает прямые запросы из Python (см. «Прямой сбор из Python» ниже). Таблицу XLSX/CSV при сборе через браузер даёт `receiver.py --export results/iphone16.xlsx` — с теми же полями, что описаны здесь.

```bash
# все страницы, результат в results/iphone16.xlsx и results/iphone16.csv
python wb_parser.py

# проверочный прогон на 3 страницах с сохранением сырых ответов API
python wb_parser.py --max-pages 3 --dump-raw raw/

# без фильтра аксессуаров, свой файл и паузы
python wb_parser.py --include-accessories -o out/all.xlsx --delay-min 2 --delay-max 5
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `-q, --query` | `iPhone 16` | поисковый запрос |
| `-p, --max-pages` | `100` | максимум страниц; сбор останавливается и раньше — на первой пустой странице |
| `--delay-min`, `--delay-max` | `1`, `3` | случайная пауза между запросами, с |
| `-o, --output` | `results/iphone16.xlsx` | путь к результату; рядом создаются `.xlsx` и `.csv` |
| `--include-accessories` | выкл. | отключить фильтр, оставить всю выдачу |
| `--min-price` | `20000` | цена ниже этой считается аксессуаром |
| `--dest` | `-1257786` | регион доставки WB (Москва); от него зависят цены и наличие. Свой регион — параметр `dest` из запроса `search` во вкладке Network |
| `--profile-dir` | `.wb_profile` | профиль браузера и кэш токена |
| `--headless` | выкл. | браузер без окна; WB его часто не пускает |
| `--browser-channel` | — | `chrome` / `msedge`: установленный браузер вместо встроенного Chromium |
| `--no-browser` | выкл. | не открывать браузер, работать только с импортированным токеном |
| `--dump-raw DIR` | — | сохранять сырые JSON страниц (для отладки разбора) |
| `-v` | — | подробный лог |

**Повторы запросов.** При 429, 5xx, таймаутах и обрывах запрос повторяется до 5 раз с экспоненциальной паузой (2, 4, 8… с; `Retry-After` учитывается).

**Сводка в конце.** Всего товаров, мин/макс/медианная цена, разбивка по моделям и объёму памяти, минимальная цена в каждой паре «модель + память».

### Фильтр аксессуаров

Товар остаётся, если выполнены все условия:

1. в названии есть «iPhone 16», «16 Plus», «16 Pro» или «16 Pro Max» (iPhone 16e и другие поколения отсекаются);
2. в названии нет слов-аксессуаров (чехол, стекло, плёнка, кабель, зарядка, адаптер, корпус, дисплей…);
3. цена не ниже `--min-price`.

Товары не в наличии (без цены) в результат не попадают. Дубли убираются по артикулу.

### Поля выходного файла

| Поле (CSV) | Колонка (XLSX) | Описание |
|---|---|---|
| `id` | Артикул | артикул WB (nm_id) |
| `name` | Название | название карточки |
| `brand` | Бренд | бренд |
| `model` | Модель | iPhone 16 / 16 Plus / 16 Pro / 16 Pro Max — из названия |
| `memory` | Память | 128 ГБ / 256 ГБ / 512 ГБ / 1 ТБ — из названия или размеров |
| `color` | Цвет | из поля `colors`, иначе из названия |
| `price` | Цена, ₽ | текущая цена (самый дешёвый размер), рубли |
| `price_basic` | Цена без скидки, ₽ | цена до скидки, рубли |
| `discount_pct` | Скидка, % | `(1 − price / price_basic) × 100` |
| `seller` | Продавец | название продавца |
| `seller_id` | ID продавца | ID продавца |
| `rating` | Рейтинг | рейтинг товара |
| `feedbacks` | Отзывов | количество отзывов |
| `url` | Ссылка | `https://www.wildberries.ru/catalog/<id>/detail.aspx` |
| `collected_at` | Дата сбора | дата и время сбора (ISO, локальное время) |

CSV сохраняется с разделителем `;` в UTF-8 с BOM, чтобы Excel открывал его без проблем с кодировкой.

## Анализ снижения цен (общий для receiver.py и monitor.py)

Настройка Telegram и запуск по расписанию ниже относятся к `monitor.py`; для `receiver.py` см. раздел выше.

### Запуск `monitor.py`

1. Скопируйте `.env.example` в `.env` и заполните:
   - `TELEGRAM_BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather);
   - `TELEGRAM_CHAT_ID` — ваш ID (например, через [@userinfobot](https://t.me/userinfobot)).

   Напишите боту `/start`, иначе он не сможет вам писать.
2. Проверка без отправки:
   ```bash
   python monitor.py --once --dry-run
   ```
3. Боевой режим.
   - Сам повторяет раз в час (окно терминала должно оставаться открытым):
     ```bash
     python monitor.py --interval 3600
     ```
   - Или через планировщик, по одному запуску за раз:
     ```bash
     python monitor.py --once
     ```

### Что анализируется

Каждый запуск сохраняет цены всех найденных смартфонов в `data/prices.sqlite` (таблицы `runs`, `products`, `observations`) и сравнивает с историей.

| Сигнал | Когда приходит |
|---|---|
| **Подешевел товар** | цена ниже прошлого наблюдения этого же артикула минимум на `--min-drop-pct` % (по умолчанию 3) **и** на `--min-drop-rub` ₽ (по умолчанию 1000) |
| 🔥 **минимум за всё время** | пометка к снижению: цена ниже всех прошлых наблюдений этого товара |
| медиана 7 дн. | пометка к снижению: медианная цена товара за неделю — видно, «скидка» это или возврат к обычной цене после подъёма |
| **Новый минимум сегмента** | самая низкая цена в паре «модель + память» (например, 16 Pro 256 ГБ) стала ниже, чем в прошлый запуск, минимум на `--min-drop-rub` ₽, в том числе за счёт нового продавца |

- **Первый запуск** создаёт базу и присылает текущие минимумы по сегментам.
- **Запуск без снижений** ничего не присылает.
- **Неудачный запуск** (не прошла проверка WB, пустая выдача) присылает ⚠️ с причиной.
- **Длинные сообщения** режутся на части (у Telegram предел 4096 символов). Снижений показывается до 25, остальные — «…и ещё N».

Дополнительные параметры: `--export results/last.xlsx` сохраняет XLSX/CSV каждого запуска, `--db` задаёт путь к базе. Остальные (`--query`, `--max-pages`, `--dest`, паузы, профиль) — как у `wb_parser.py`.

### Запуск раз в час через планировщик

**Linux (cron)**, `crontab -e`:
```cron
5 * * * * cd /path/to/WB-Parser && .venv/bin/python monitor.py --once >> monitor.log 2>&1
```
На сервере без экрана браузеру нужен виртуальный дисплей: `xvfb-run -a .venv/bin/python monitor.py --once`.

**Windows (Планировщик заданий).** Создать задачу:
- триггер — ежедневно, повторять каждый 1 час;
- действие — программа `C:\path\WB-Parser\.venv\Scripts\python.exe`, аргументы `monitor.py --once`, рабочая папка `C:\path\WB-Parser`.



## Прямой сбор из Python: Playwright и импорт токена

`wb_parser.py` и `monitor.py` получают токен в браузере, а затем запрашивают API из Python. На момент написания WB это не пропускает:
- браузер под управлением Playwright получает «Подозрительная активность» даже с российского домашнего IP;
- токен, импортированный из обычного браузера (`python3 wb_token.py import --curl curl.txt`), получает `498`.

Если WB ослабит защиту, способ может заработать снова. Проверить: `python3 wb_token.py check`. Нужна установка браузера: `playwright install chromium`.

Флаги токена у `wb_parser.py` и `monitor.py`:
- `--no-browser` — работать только с импортированным токеном;
- `--browser-channel chrome` — запускать установленный Chrome вместо встроенного Chromium.

> `token.json` и `curl.txt` содержат ваши cookie WB (если вы залогинены — и сессию аккаунта). Они в `.gitignore`; никому их не передавайте.

## Тесты

```bash
python -m pytest -q
```

Тесты проверяют разбор ответа, фильтр, дедупликацию, повторы запросов, обновление токена, экспорт, анализ снижений, приёмник и userscript. Userscript проверяется в Chromium против поддельного «WB» на localhost; нужен `playwright install chromium`, иначе этот тест пропускается. Они работают на синтетических ответах, поэтому соответствие реальному формату API ими не гарантируется.

## Если что-то не так с данными

При сборе через браузер: запустите `python3 receiver.py --dump-raw raw/ -v` — каждая присланная выдача сохранится в `raw/ingest_*.json`. Если плашка во вкладке показывает ошибку, подробности — в консоли Firefox (F12 → Консоль, строки `[WB-мониторинг]`).

Формат API Wildberries не документирован и меняется. Если цены пустые, модель или память не определяются или товаров 0:

1. запустите `python wb_parser.py --max-pages 1 --dump-raw raw/ -v`;
2. посмотрите `raw/page_001.json`.

Разбор ожидает:
- список товаров в `products` (или `data.products`);
- цены в копейках в `sizes[].price.product` / `sizes[].price.basic` (или в старых полях `salePriceU` / `priceU`);
- продавца в `supplier`, рейтинг в `reviewRating`, отзывы в `nmFeedbacks` / `feedbacks`, цвет в `colors[].name`.

Если структура другая, поправьте `parse_items` и `_extract_prices` в `wb_parser.py`.

Автоматический сбор данных формально не разрешён правилами Wildberries. Держите разумную частоту — раз в час с паузами 1–3 с между страницами.
