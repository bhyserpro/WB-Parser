# WB-Parser — цены и снижения цен на iPhone 16 с Wildberries

Два инструмента:

- **`wb_parser.py`** — разовый сбор выдачи по запросу «iPhone 16» во все страницы, фильтр аксессуаров, экспорт в CSV и XLSX, сводка в консоль.
- **`monitor.py`** — запуск раз в час: сбор, сохранение истории цен в SQLite, анализ снижений и уведомления в Telegram.

## Как это работает

Выдача берётся из того же JSON API, что использует сам сайт:
`https://www.wildberries.ru/__internal/search/exactmatch/ru/common/v18/search`.
Это быстрее и надёжнее разбора HTML.

API закрыт антиботом WB: без cookie `x_wbaas_token` он отвечает 403/498, а токен выдаёт только JS-проверка в браузере. Поэтому:

1. **Токен.** `wb_token.py` открывает страницу поиска в Chromium через Playwright, ждёт, пока сайт сам загрузит выдачу, и сохраняет cookie и User-Agent браузера в `.wb_profile/token.json`. Профиль браузера постоянный.
2. **Сбор.** Дальше все страницы запрашиваются обычным `requests` с этими cookie.
3. **Обновление токена.** Если токен протух (401/403/498), браузер открывается снова — один раз за запуск.

> ⚠️ **Запускайте с российского «домашнего» IP**: ваш ПК, мини-ПК, Raspberry Pi. С IP дата-центров и зарубежных VPN WB показывает «Подозрительная активность» даже настоящему браузеру. Российский VPS может работать, а может нет — это проверяется только запуском.

## Установка

Нужен Python 3.11+.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
```

При первом запуске откроется окно Chromium. Если WB покажет капчу, решите её руками; дальше токен берётся из профиля.

### Если WB пишет «Подозрительная активность»

Это значит, что WB не пустил браузер под управлением скрипта: распознал автоматизацию. Возьмите токен из своего обычного браузера, где проверку проходите вы сами:

1. Откройте в Chrome/Edge/Яндекс.Браузере `https://www.wildberries.ru/catalog/0/search.aspx?search=iPhone%2016`, дождитесь товаров.
2. F12 → **Network** → в фильтре `search` → запрос `search?...` → правый клик → **Copy → Copy as cURL (bash)**. Именно *bash*, не *cmd*.
3. Вставьте в файл `curl.txt` в папке проекта и выполните:
   ```bash
   python wb_token.py import --curl curl.txt
   ```
   Команда сохранит cookie и User-Agent в `.wb_profile/token.json` и сразу проверит токен запросом к API.
4. Запускайте парсер и монитор с `--no-browser`, чтобы они не пытались открыть браузер:
   ```bash
   python wb_parser.py --max-pages 3 --no-browser --dump-raw raw/
   ```

Когда токен протухнет, монитор пришлёт в Telegram ⚠️ «Токена нет или он устарел» — повторите шаги 1–3. Проверить текущий токен: `python wb_token.py check`.

Ещё один вариант — вместо встроенного Chromium запустить установленный Google Chrome: `--browser-channel chrome`. Его WB иногда пропускает охотнее, но гарантии нет.

> `token.json` и `curl.txt` содержат ваши cookie WB (если вы залогинены — и сессию аккаунта). Они в `.gitignore`; никому их не передавайте. `curl.txt` после импорта можно удалить.

## Разовый сбор: `wb_parser.py`

```bash
# все страницы, результат в results/iphone16.xlsx и results/iphone16.csv
python wb_parser.py

# проверочный прогон на 3 страницах с сохранением сырых ответов API
python wb_parser.py --max-pages 3 --dump-raw raw/

# без фильтра аксессуаров, свой файл и паузы
python wb_parser.py --include-accessories -o out/all.xlsx --delay-min 2 --delay-max 5
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `-q, --query` | `iPhone 16` | поисковый запрос |
| `-p, --max-pages` | `100` | максимум страниц; сбор останавливается и раньше — на первой пустой странице |
| `--delay-min`, `--delay-max` | `1`, `3` | случайная пауза между запросами, с |
| `-o, --output` | `results/iphone16.xlsx` | путь к результату; рядом создаются `.xlsx` и `.csv` |
| `--include-accessories` | выкл. | отключить фильтр, оставить всю выдачу |
| `--min-price` | `20000` | цена ниже этой считается аксессуаром |
| `--dest` | `-1257786` | регион доставки WB (Москва); от него зависят цены и наличие. Свой регион — параметр `dest` из запроса `search` во вкладке Network |
| `--profile-dir` | `.wb_profile` | профиль браузера и кэш токена |
| `--headless` | выкл. | браузер без окна; WB его часто не пускает |
| `--browser-channel` | — | `chrome` / `msedge`: установленный браузер вместо встроенного Chromium |
| `--no-browser` | выкл. | не открывать браузер, работать только с импортированным токеном |
| `--dump-raw DIR` | — | сохранять сырые JSON страниц (для отладки разбора) |
| `-v` | — | подробный лог |

**Повторы запросов.** При 429, 5xx, таймаутах и обрывах запрос повторяется до 5 раз с экспоненциальной паузой (2, 4, 8… с; `Retry-After` учитывается).

**Сводка в конце.** Всего товаров, мин/макс/медианная цена, разбивка по моделям и объёму памяти, минимальная цена в каждой паре «модель + память».

### Фильтр аксессуаров

Товар остаётся, если выполнены все условия:

1. в названии есть «iPhone 16», «16 Plus», «16 Pro» или «16 Pro Max» (iPhone 16e и другие поколения отсекаются);
2. в названии нет слов-аксессуаров (чехол, стекло, плёнка, кабель, зарядка, адаптер, корпус, дисплей…);
3. цена не ниже `--min-price`.

Товары не в наличии (без цены) в результат не попадают. Дубли убираются по артикулу.

### Поля выходного файла

| Поле (CSV) | Колонка (XLSX) | Описание |
|---|---|---|
| `id` | Артикул | артикул WB (nm_id) |
| `name` | Название | название карточки |
| `brand` | Бренд | бренд |
| `model` | Модель | iPhone 16 / 16 Plus / 16 Pro / 16 Pro Max — из названия |
| `memory` | Память | 128 ГБ / 256 ГБ / 512 ГБ / 1 ТБ — из названия или размеров |
| `color` | Цвет | из поля `colors`, иначе из названия |
| `price` | Цена, ₽ | текущая цена (самый дешёвый размер), рубли |
| `price_basic` | Цена без скидки, ₽ | цена до скидки, рубли |
| `discount_pct` | Скидка, % | `(1 − price / price_basic) × 100` |
| `seller` | Продавец | название продавца |
| `seller_id` | ID продавца | ID продавца |
| `rating` | Рейтинг | рейтинг товара |
| `feedbacks` | Отзывов | количество отзывов |
| `url` | Ссылка | `https://www.wildberries.ru/catalog/<id>/detail.aspx` |
| `collected_at` | Дата сбора | дата и время сбора (ISO, локальное время) |

CSV сохраняется с разделителем `;` в UTF-8 с BOM, чтобы Excel открывал его без проблем с кодировкой.

## Мониторинг снижения цен: `monitor.py`

1. Скопируйте `.env.example` в `.env` и заполните:
   - `TELEGRAM_BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather);
   - `TELEGRAM_CHAT_ID` — ваш ID (например, через [@userinfobot](https://t.me/userinfobot)).

   Напишите боту `/start`, иначе он не сможет вам писать.
2. Проверка без отправки:
   ```bash
   python monitor.py --once --dry-run
   ```
3. Боевой режим.
   - Сам повторяет раз в час (окно терминала должно оставаться открытым):
     ```bash
     python monitor.py --interval 3600
     ```
   - Или через планировщик, по одному запуску за раз:
     ```bash
     python monitor.py --once
     ```

### Что анализируется

Каждый запуск сохраняет цены всех найденных смартфонов в `data/prices.sqlite` (таблицы `runs`, `products`, `observations`) и сравнивает с историей.

| Сигнал | Когда приходит |
|---|---|
| **Подешевел товар** | цена ниже прошлого наблюдения этого же артикула минимум на `--min-drop-pct` % (по умолчанию 3) **и** на `--min-drop-rub` ₽ (по умолчанию 1000) |
| 🔥 **минимум за всё время** | пометка к снижению: цена ниже всех прошлых наблюдений этого товара |
| медиана 7 дн. | пометка к снижению: медианная цена товара за неделю — видно, «скидка» это или возврат к обычной цене после подъёма |
| **Новый минимум сегмента** | самая низкая цена в паре «модель + память» (например, 16 Pro 256 ГБ) стала ниже, чем в прошлый запуск, минимум на `--min-drop-rub` ₽, в том числе за счёт нового продавца |

- **Первый запуск** создаёт базу и присылает текущие минимумы по сегментам.
- **Запуск без снижений** ничего не присылает.
- **Неудачный запуск** (не прошла проверка WB, пустая выдача) присылает ⚠️ с причиной.
- **Длинные сообщения** режутся на части (у Telegram предел 4096 символов). Снижений показывается до 25, остальные — «…и ещё N».

Дополнительные параметры: `--export results/last.xlsx` сохраняет XLSX/CSV каждого запуска, `--db` задаёт путь к базе. Остальные (`--query`, `--max-pages`, `--dest`, паузы, профиль) — как у `wb_parser.py`.

### Запуск раз в час через планировщик

**Linux (cron)**, `crontab -e`:
```cron
5 * * * * cd /path/to/WB-Parser && .venv/bin/python monitor.py --once >> monitor.log 2>&1
```
На сервере без экрана браузеру нужен виртуальный дисплей: `xvfb-run -a .venv/bin/python monitor.py --once`.

**Windows (Планировщик заданий).** Создать задачу:
- триггер — ежедневно, повторять каждый 1 час;
- действие — программа `C:\path\WB-Parser\.venv\Scripts\python.exe`, аргументы `monitor.py --once`, рабочая папка `C:\path\WB-Parser`.

## Тесты

```bash
python -m pytest -q
```

Тесты проверяют разбор ответа, фильтр, дедупликацию, повторы запросов, обновление токена, экспорт и анализ снижений. Они работают на синтетических ответах, поэтому соответствие реальному формату API ими не гарантируется.

## Если что-то не так с данными

Формат API Wildberries не документирован и меняется. Если цены пустые, модель или память не определяются или товаров 0:

1. запустите `python wb_parser.py --max-pages 1 --dump-raw raw/ -v`;
2. посмотрите `raw/page_001.json`.

Разбор ожидает:
- список товаров в `products` (или `data.products`);
- цены в копейках в `sizes[].price.product` / `sizes[].price.basic` (или в старых полях `salePriceU` / `priceU`);
- продавца в `supplier`, рейтинг в `reviewRating`, отзывы в `nmFeedbacks` / `feedbacks`, цвет в `colors[].name`.

Если структура другая, поправьте `parse_items` и `_extract_prices` в `wb_parser.py`.

Автоматический сбор данных формально не разрешён правилами Wildberries. Держите разумную частоту — раз в час с паузами 1–3 с между страницами.
